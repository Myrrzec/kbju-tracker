# KBJU Tracker — архитектура и план

## Что это
Веб-приложение для учёта КБЖУ: дневник питания, личный профиль с целями,
распознавание еды по фото через AI, персональные рекомендации от AI.

## Стек
- **Backend**: Python + FastAPI (sync SQLAlchemy 2.0, т.к. нагрузка небольшая и так проще отлаживать)
- **DB**: PostgreSQL + Alembic (миграции)
- **Auth**: JWT (access + refresh)
- **AI**: Claude (Anthropic API) — vision для распознавания фото, текст для рекомендаций
- **Хранение фото**: локальный диск на MVP через абстракцию `StorageBackend` (легко заменить на S3 позже)

## Доменная модель
- **User** — учётка (email/password)
- **UserProfile** — личные данные: пол, возраст, рост, вес, уровень активности, цель (похудение/поддержание/набор), рассчитанные/переопределённые целевые КБЖУ
- **FoodItem** — справочник продуктов (КБЖУ на 100г), источник: базовый набор / AI-оценка / пользователь
- **MealEntry** — запись в дневнике: что съедено, сколько грамм, КБЖУ (снэпшот на момент записи, не пересчитывается задним числом), время приёма пищи, источник (ручной ввод / фото)
- **Recommendation** — сгенерированная AI-рекомендация, привязанная к периоду

## API (v1)
| Группа | Эндпоинты |
|---|---|
| Auth | `POST /auth/register`, `POST /auth/login`, `POST /auth/refresh` |
| Профиль | `GET/PUT /users/me/profile`, `GET /users/me/targets` |
| Дневник | `POST/GET/PUT/DELETE /diary/entries`, `GET /diary/summary?date=` |
| Распознавание | `POST /recognition/photo` (фото → кандидаты блюд с КБЖУ, ещё не сохранено) |
| Рекомендации | `GET /recommendations`, `POST /recommendations/generate` |

## Расчёт целевых КБЖУ
Формула Миффлина-Сан Жеора (BMR) × коэффициент активности → TDEE → корректировка под цель
(-500 ккал для похудения, +500 для набора). Белки считаются от массы тела, жиры — от
калорийности, углеводы — остаток. Детали в [`app/services/nutrition_calc.py`](../backend/app/services/nutrition_calc.py).

## AI-промпты
Вынесены отдельно и задокументированы в [`docs/PROMPTS.md`](PROMPTS.md) — их придётся итеративно
подстраивать по мере тестирования на реальных фото и отзывах пользователей.

- Распознавание фото → строго структурированный JSON через tool use (Claude сам не может
  "разговориться" вместо структуры)
- Рекомендации → текстовый ответ на основе профиля + сводки за последние N дней

## Что сознательно отложено (не переусложняем MVP)
- Refresh-token blacklist / logout-инвалидация — на MVP короткий access-токен + ротация refresh
- Внешняя база продуктов (Open Food Facts и т.п.) — пока справочник наполняется вручную и через AI-оценки
- Async SQLAlchemy — не нужен при текущих нагрузках, усложнил бы код без пользы
